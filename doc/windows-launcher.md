# Запуск WebReport в Windows

После первоначальной настройки дважды нажмите `Start-WebReport.cmd` в корне репозитория. Скрипт при необходимости запускает Docker Desktop, поднимает сервисы, дожидается готовности и открывает браузер. Повторный запуск использует существующие контейнеры и данные.

Для остановки нажмите `Stop-WebReport.cmd` в корне. Том базы и история диалогов сохраняются. Закрытие браузера само по себе сервисы не останавливает. Скрипт останавливает общий стек WebReport; это не отдельный экземпляр для каждого датасета.

Файлы `.cmd` вызывают `scripts/WebReport.ps1` относительно своего расположения, поэтому запуск не зависит от текущей папки терминала. Порт интерфейса читается из сгенерированного `webreport/.env`.

## Первоначальная настройка

Это средство повседневного запуска уже настроенного проекта. Нужны Windows PowerShell 5.1 или новее, Docker Desktop с Linux-контейнерами, Git for Windows с Bash, GNU Make, Poetry и установленное окружение проекта. Базовую настройку и конфигурацию см. в корневом `README.md`; для внешнего датасета выполните его инструкцию развёртывания.

Docker, Git, Make и Poetry ищутся в `PATH`. Для Docker и Git также проверяются стандартные пользовательские и системные каталоги установки. Для Make и Poetry поддерживаются локальные установки в `range/.setup/msys-make/usr/bin` и `range/.setup/poetry/Scripts`, если они уже подготовлены на компьютере. Сами программы и локальные данные через Git не передаются.

## Локальный выбор датасета

Без настройки запускается стандартный датасет проекта, как при `make webreport-start`. Для сохранения выбора внешнего датасета можно создать `range/webreport-launcher.json`:

```json
{
  "dataset": "my_dataset",
  "datasetDir": "D:/Analytics/my_dataset"
}
```

`datasetDir` необязателен: по умолчанию используется `range/<dataset>`. Относительный путь считается от корня репозитория. Этот файл остаётся локальным благодаря `.gitignore`; ключи в нём не нужны. Набор данных должен предоставлять `config/config.local.toml` по существующему контракту проекта.

Если в `Makefile` датасета явно объявлены цели `db-up` и `db-down`, соответствующая цель выполняется при запуске или остановке. Иначе скрипт управляет только WebReport, а внешняя база должна быть запущена отдельно. Сброс базы и удаление томов скрипт не выполняет.

Для разового выбора можно передать `-Dataset my_dataset -DatasetDir "D:/Analytics/my_dataset"` файлу запуска. Также поддерживаются существующие переменные окружения `DATASET` и `DATASET_DIR`; параметры команды имеют приоритет, а JSON используется при отсутствии выбранного датасета. Для запуска без открытия вкладки передайте `-NoBrowser`.

JSON выбирает операторский датасет backend. Проекты и API-источники (Метрика, GA4 и другие) добавляются уже в новом интерфейсе: [инструкция](../webreport/frontend-web/README.md). При запуске frontend пересобирается; Node.js на хосте не требуется. Интерфейс доступен и при временно недоступной модели, чтобы можно было подключить собственный ключ.
