## Введение

Система веб-отчётов позволяет генерировать аналитические отчёты по данным игр через простой диалог с AI-агентом. Вы описываете что хотите увидеть на естественном языке, а система автоматически создаёт соответствующий отчёт.

### Основные возможности

- 💬 **Диалог с AI**: Описывайте требования к отчёту на русском языке
- 📊 **Визуализация**: Таблицы, графики, метрики
- 📥 **Экспорт**: Сохранение отчётов в CSV
- 🔄 **История**: Сохранение и просмотр истории диалогов
- 🎯 **Гибкость**: Различные типы запросов и отчётов

## Знания о предметной области (для оператора)

Этот раздел предназначен для оператора, который обслуживает развёртывание и редактирует файлы знаний. Пользователю чата ничего здесь менять не нужно: он задаёт вопросы в интерфейсе, а агент читает подготовленные оператором темы.

### Структура папки

Знания читаются один раз при запуске backend. По умолчанию `knowledge_dir` ведёт к поставляемой папке `bd_shared/knowledge/bez_durakov`:

```text
bd_shared/
└── knowledge/
    └── bez_durakov/
        ├── manifest.toml
        ├── glossary.md
        ├── rules.md
        └── scoring.md
```

В корне папки обязателен `manifest.toml`. Каждый обычный файл `.md` в этом корне становится темой, скрытые файлы пропускаются, а подкаталог делает папку недействительной. Поставляемый `bd_shared/knowledge/bez_durakov/rules.md` является скелетом, который оператор заполняет настоящими правилами. Ни изменения кода, ни новый деплой для этого не нужны, после сохранения достаточно перезапустить стек.

### Манифест

`manifest.toml` содержит ровно два ключа. Любой дополнительный ключ отклоняется.

- `dataset` соответствует имени настроенной базы данных. Значение должно полностью соответствовать шаблону `^[a-z0-9_-]{1,64}$`, состоять из строчных латинских букв, цифр, `_` или `-` и совпадать с именем базы данных. В поставляемом примере это `bez_durakov`.
- `persona` задаёт роль, тон и язык ответов агента. Это непустая строка длиной не более `knowledge_max_persona_chars` символов.

Например:

```toml
dataset = "bez_durakov"
persona = """Ты аналитик данных. Отвечай по-русски."""
```

`persona` задаёт общую манеру ответа. Подробные правила предметной области остаются в теме `rules.md`.

### Темы, идентификаторы и краткое описание

Имя файла задаёт идентификатор темы. У файла `rules.md` идентификатор `rules`; часть имени до `.md` должна полностью соответствовать `^[a-z0-9_-]{1,40}$`. Прописные буквы, пробелы и другие символы недопустимы.

Заголовок темы берётся из первой строки, которая соответствует `^#{1,6}\s+\S`. Из неё удаляются только начальные `#` и окружающие пробелы. Получившийся заголовок не может быть длиннее `knowledge_max_title_chars` символов.

Первый непустой блок после этого заголовка становится кратким описанием темы. Пустые строки перед ним пропускаются, а строки блока соединяются одним пробелом. Его длина не может быть больше `knowledge_max_summary_chars` символов. Первой строкой этого блока должен быть обычный текст. Если после заголовка первым непустым блоком идёт список, нумерованный список, ограждение кода, таблица, цитата, новый заголовок или HTML-блок, документ будет отклонён. Поэтому сразу после заголовка не ставьте список, кодовый блок, таблицу, цитату или заголовок.

```markdown
# Название темы

Первый простой абзац становится кратким описанием темы.

Далее можно добавить подробности, примеры и разделы.
```

### Настройки `[webreport]`

В `bd_shared/config.toml` раздел `[webreport]` задаёт следующие значения по умолчанию:

| Ключ | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `knowledge_dir` | `"knowledge/bez_durakov"` | Путь к папке знаний относительно `bd_shared`; пустое значение отключает загрузку знаний. |
| `knowledge_max_title_chars` | `80` | Максимальная длина заголовка темы. |
| `knowledge_max_summary_chars` | `200` | Максимальная длина первого абзаца, который становится кратким описанием. |
| `knowledge_max_persona_chars` | `2000` | Максимальная длина `persona` в манифесте. |
| `knowledge_max_topics` | `50` | Максимальное число файлов тем. |
| `knowledge_max_doc_bytes` | `65536` | Максимальный размер одного файла темы в байтах. |
| `knowledge_max_bytes_per_turn` | `131072` | Суммарный лимит байтов документов, прочитанных за один вопрос пользователя, когда вопрос охватывает несколько больших тем. |

Первые шесть ключей уже читаются из текущей конфигурации. Значение `131072` для `knowledge_max_bytes_per_turn` сейчас передаётся при запуске напрямую; отдельный ключ конфигурации добавляется работой C10 и сохранит это значение по умолчанию.

### Сообщения при запуске

Папка отсутствует или не настроена, backend продолжает работу без знаний. Папка с ошибкой манифеста или документа останавливает запуск. В логах используются следующие точные шаблоны:

| Ситуация | Строка лога | Результат |
| --- | --- | --- |
| `knowledge_dir` не задан | `Knowledge folder is not configured (webreport.knowledge_dir is unset); the agent runs without dataset knowledge.` | Запуск продолжается без знаний. |
| Папка по указанному пути не найдена | `Knowledge folder not found at %s; the agent runs without dataset knowledge.` | Запуск продолжается без знаний. |
| Манифест или тема не прошли проверку | `Knowledge folder is invalid: %s` | Запуск прерывается. |

В шаблонах `%s` заменяется фактическим путём или подробностью ошибки. После успешной загрузки будет информационная строка `Knowledge loaded: dataset=%s, topics=%d`.

## Работа с чатом

### Ввод требований

1. Выберите **💬 Чат** в боковой панели
2. Введите ваш запрос в текстовое поле
3. Нажмите кнопку **Отправить**
4. Дождитесь генерации отчёта

### Формулировка запросов

Система понимает естественный язык. Примеры:

**Простые запросы:**
- "покажи все игры"
- "список всех команд"
- "покажи очки команд"

**Запросы с фильтрацией:**
- "топ 10 команд по очкам"
- "статистика команды Название"
- "игры за последний месяц"

**Аналитические запросы:**
- "какая команда лучше всего играет в преф?"
- "средние очки команд по категориям"
- "сравни две команды"

### История диалога

В чате отображаются:
- 👤 **Ваши сообщения** (голубой фон)
- 🤖 **Ответы ассистента** (серый фон)
- ⏰ Временные метки
- ✅ Статус выполнения запроса

## Просмотр отчётов

### Переключение на отчёт

1. После генерации отчёта появится сообщение: "✅ Отчёт сгенерирован!"
2. Переключитесь на **📊 Отчёт** в боковой панели
3. Отчёт отобразится с данными и визуализацией

### Элементы отчёта

**Метрики (если доступны):**
- Всего записей
- Средние значения
- Количество уникальных элементов

**Таблица данных:**
- Полные данные в табличном виде
- Сортировка по столбцам
- Прокрутка для больших наборов данных

**Визуализация:**
- Графики для числовых данных
- Выбор колонки для визуализации
- Интерактивные элементы

**Экспорт:**
- Кнопка **📥 Скачать CSV**
- Файл сохраняется с временной меткой
- Формат: `report_YYYYMMDD_HHMMSS.csv`

### Обновление отчёта

Чтобы сгенерировать новый отчёт:
1. Вернитесь в **💬 Чат**
2. Введите новые требования
3. Отчёт обновится автоматически

## Часто задаваемые вопросы

### Общие вопросы

**Q: Система не понимает мой запрос. Что делать?**

A: Попробуйте:
- Переформулировать запрос проще
- Использовать ключевые слова: "игры", "команды", "очки", "статистика"
- Посмотреть примеры выше

**Q: Как очистить историю диалога?**

A: Нажмите кнопку **🗑️ Очистить чат** в боковой панели

**Q: Можно ли экспортировать отчёт?**

A: Да, используйте кнопку **📥 Скачать CSV** в представлении отчёта

**Q: Система работает без OpenAI API?**

A: Да, в fallback режиме. Некоторые сложные запросы могут работать упрощённо.

### Технические вопросы

**Q: Backend не запускается**

A: Проверьте:
1. Docker контейнеры запущены: `docker compose ps`
2. Логи контейнера: `make logs` или `docker compose logs backend`
3. Контейнер MySQL доступен backend по имени `mysql` на порту `3306`
4. Файл bd_shared/config.toml существует в родительской директории

**Q: Frontend показывает "API недоступен"**

A: 
1. Проверьте статус backend: `curl http://localhost:28000/health`
2. Проверьте контейнеры: `docker compose ps`
3. Посмотрите логи: `docker compose logs frontend`
4. Перезапустите: `make restart`

**Q: Ошибка "Database connection failed"**

A:
1. Проверьте сервис MySQL: `docker compose ps mysql`
2. Проверьте настройки в `../bd_shared/config.toml`
3. Проверьте подключение из контейнера:
   ```bash
   docker compose exec backend python -c "import socket; print(socket.gethostbyname('mysql'))"
   ```

**Q: Как использовать с настоящими AI агентами?**

A:
1. Создайте `bd_shared/config.local.toml` из `config.local.toml.example`
2. Укажите ключ в `[webreport].openai_api_key` файла `bd_shared/config.local.toml`
3. Запустите или перезапустите стек: `make start` / `make restart`
4. Учтите, что Compose и service env-файлы генерируются `generate_env.py` из объединённых `bd_shared/config.toml` и `config.local.toml`

### Вопросы по данным

**Q: Какие типы отчётов доступны?**

A: В текущей версии:
- Список всех игр
- Список всех команд
- Очки команд по играм
- Статистика отдельной команды

**Q: Можно ли фильтровать по датам?**

A: Да, используйте запросы типа "игры за период..." (функционал расширяется)

A: Запросите "покажи все команды"

**Q: Данные обновляются в реальном времени?**

A: Да, данные берутся напрямую из базы данных при каждом запросе
