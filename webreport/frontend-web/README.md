# Dig AI — рабочее пространство WebReport

Универсальные инструменты анализа, изолированный Python и графики в правой панели описаны в [ANALYSIS.md](../ANALYSIS.md). Для проверки интерфейса на синтетических данных откройте `/tests/workspace.html?analysis` в Vite.

Основной интерфейс WebReport: React, TypeScript и Vite. Docker собирает статические файлы и раздаёт их через nginx; `/api` проксируется в FastAPI. `frontend/` — сохранённый legacy Streamlit-клиент, в основном Compose он больше не запускается и не развивается.

## Запуск и разработка

Обычный запуск: `Start-WebReport.cmd` в корне или `make webreport-start`. Сборка интерфейса входит в запуск. Node.js на хосте для Docker не нужен.

Для разработки с уже работающим backend:

```powershell
cd webreport/frontend-web
npm ci
npm run dev
```

Vite использует `http://127.0.0.1:28000`. При другом порте задайте `WEBREPORT_DEV_API`. Проверка типов и production-сборка: `npm run build`.

## Персонаж и проверка анимации

По умолчанию помощник — объёмная лопата с глазами. `src/mascot/shovel-model.ts` создаёт геометрию лезвия, ручки, глаз, скруглённых бровей, травы и флага; `shovel-scene.ts` отвечает за Three.js, свет, вращение и реакции. Рты меняются из прозрачного атласа 4×4, нарисованный остров отображается позади геометрии, а тень падает на прозрачную плоскость с границей по нарисованной поверхности острова. Камера, свет и остров закреплены. Лопата вращается вокруг нижней точки лезвия: полный поворот по горизонтали и ручной наклон до 10° в обе стороны. Флаг всегда развевается вправо на экране. Приветствие и подсказки помощника находятся в комиксовой реплике, движение рта сопровождает появление текста. `SpeechBubble.tsx` рисует скруглённое облачко и хвостик единым SVG-контуром с общей заливкой, обводкой и тенью; контур подстраивается под высоту текста и расположение рядом с персонажем или над ним. Сцена загружается отдельным модулем только при выборе лопаты. `Companion.tsx` сохраняет один canvas при перелёте из приветствия к полю ввода и хранит выбор помощника в `wr-companion`. В локальном профиле доступны «Лопата · 3D», прежний «Исследователь» и «Без персонажа». Генеративные иллюстрации и промпты находятся в `public/mascot/`, новый значок — в `public/brand/`.

Перетаскивание вращает только лопату; стрелки делают то же с клавиатуры, Home возвращает исходную позу. `shovel-rotation.ts` обрабатывает мышь, касания и клавиатуру; поворот применяется к отдельному пивоту персонажа. Нажатие, Enter и пробел вызывают приветствие, радость или короткую раскопку. При вводе лопата обращает лицо и взгляд к зрителю; состояние задания управляет остальными реакциями. Флаг, трава и моргание анимируются независимо. Рендер использует антиалиасинг, масштаб холста 2×, отражения от локально созданного окружения и тени. Цикл ограничен 30 кадрами в секунду и останавливается вне экрана, в фоновой вкладке, при выключенной анимации или системном уменьшении движения. Без анимации ручное вращение остаётся доступным. При смене персонажа освобождаются геометрия, материалы, WebGL-контекст и обработчики.

[Сгенерированный образ и точный промпт](public/mascot/README.md) служат визуальным ориентиром; иллюстрация также показывается при отсутствии WebGL 2 или потере контекста. Кнопка повтора позволяет восстановить объёмную сцену. Сохранённый SVG-исследователь находится в `Expedition.tsx` и `rig.ts`: фронтальный ракурс, крупная голова, парящие кисти, без суставов и обратной кинематики.

Во время выполнения вопроса лопата говорит «Копаю…» и повторяет цикл из `digging.ts`: медленный подъём, быстрый удар, наклон для поддевания земли, выброс и короткая задумчивая пауза. Маска глубины повторяет поверхность острова, а плоскость отсечения скрывает зарывшуюся часть лезвия и её тень. При ударе появляется раскопанная земля, комочки летят по баллистическим траекториям, отскакивают и исчезают. После ответа земля плавно возвращается к исходному виду. Ручное перетаскивание временно приостанавливает копание; окружение остаётся неподвижным.

`npm test` проверяет объём и корректность геометрии, ограничение сложности сцены, неподвижность окружения и точки опоры при поворотах лопаты, совпадение границы тени с поверхностью острова, маску земли, фазы копания и траектории частиц, управление мышью и клавиатурой, крепление флага, освобождение общих ресурсов и прежнюю SVG-анимацию. После `npm run dev` страница `/tests/shovel.html` показывает крупную 3D-сцену и все реакции; `?fallback` имитирует один отказ WebGL для проверки иллюстрации и восстановления кнопкой. `/tests/mascot.html` показывает эмоции исследователя. `/tests/design.html` позволяет проверить оформление переписки и поля ввода. `/tests/workspace.html` запускает настоящий App на синтетическом API: отправка → размышление → инструмент → ответ либо отмена. Эти страницы не входят в production-сборку и не вызывают модели или реальные сервисы.

## Работа с интерфейсом

- Название интерфейса — Dig AI; WebReport остаётся техническим названием компонента и команд запуска. Светлое оформление сочетает лиловый фон, коралловый акцент, далёкие силуэты и траву. В открытой переписке фон менее заметен.
- «Локальный профиль → Акцентный цвет» меняет оформление сразу: шесть палитр и произвольный цвет. Выбор сохраняется в этом браузере. Акцент используется в навигации и кнопках; графики и выбранные карточки показателей имеют самостоятельную контрастную палитру. Сообщения пользователя имеют самостоятельный лавандовый фон с мягкой тенью. Фирменные значки сервисов сохраняют свои цвета. Цвет подписей на акцентных кнопках автоматически выбирается по контрасту. Уже сохранённый акцент сохраняется; новый цвет по умолчанию — «Коралл».
- Поверхности основных кнопок и поля ввода — скруглённые трапеции со скосом около 3° от вертикали у кнопок и 1,25° у поля ввода. SVG-подложка адаптируется к размеру, текст и области нажатия остаются прямоугольными; меню и увеличенное поле ввода не обрезаются.
- Боковая панель плавно выезжает и скрывается, учитывает системное уменьшение анимации и сохраняет состояние папок. Папку можно переключить нажатием на всю её строку (кроме отдельных кнопок действий), в том числе на название. Названия текущего проекта и чата остаются в боковой панели.
- Новый чат встречает фразой «Хей. Какие вопросы по проекту?». В пустом проекте — «Yo, чел. Мне нужна инфа, чтобы дать тебе толковые советы» и крупная кнопка добавления источника. Над приветствием живёт выбранный помощник; с началом переписки он перемещается в угол у поля ввода.
- Помощник копает при работе инструмента, думает во время подготовки ответа, радуется завершению и реагирует на ошибку. «Живая анимация» в настройках останавливает движения персонажа, флага и травы; системное уменьшение движения также учитывается.
- Источники находятся внутри поля ввода: значок сервиса, название и состояние подключения. Плашка открывает отчёт сразу на весь экран; при утраченном или отклонённом ключе — форму его повторного ввода. Ошибки подключения отмечены восклицательным знаком; временные ошибки сервиса можно повторить в отчёте. Статус обновляется после запросов, при возвращении во вкладку и перед открытием источника. Данные операторского проекта учитываются только когда API-источников нет, как в backend.
- Настройки источника показывают ID и остальные несекретные параметры, а также наличие действующего ключа. Его можно оставить при сохранении настроек или заменить. Списки сервисов, регионов и периодов оформлены выбранным акцентным цветом и доступны с клавиатуры: стрелки, Home/End, ввод начала названия, Enter и Escape.
- Под ответом находятся копирование, название модели, длительность и локальное время получения. Длительность новых ответов сохраняется сервером в `duration_seconds`; старая история без этого поля показывает имеющиеся сведения. У сообщений нет аватаров.
- Значки сервисов загружаются из локальных файлов; [список оригинальных источников](public/providers/README.md).
- Проекты и чаты находятся слева. Источники проекта доступны всем его чатам; новый проект начинает без источников. Плюс у папки открывает новый чат, который сохраняется с первым сообщением.
- Подключения добавляются через «Источники» в шапке или плюс в поле ввода. Нажатие на название источника открывает сводку. Подробные разделы загружаются при выборе; таблицы Метрики листаются по 50 строк. Период ограничен 366 днями. Правила кеширования конструктора Метрики описаны ниже.
- В отчёте разделы расположены в левом сайдбаре; на телефоне он сужается до значков с подписями. Панель периода содержит «Сегодня», «Вчера», последние 7/30/90 полных дней и выбор произвольных дат с кнопкой «Применить». Календарь показывает 2–4 месяца на широком экране и один на телефоне; диапазон выбирается двумя нажатиями или вводом дат. Стрелки, Home/End и PageUp/PageDown перемещают фокус, Escape отменяет выбор. Для Метрики сегодня определяется в часовом поясе счётчика, для остальных источников — браузера. Активное выделение перемещается между кнопками. Точки графика соединены прямыми отрезками, нижняя ось выделена сплошной линией; отрисовка занимает 500 мс. Подсказка появляется сразу на месте и только затем перемещается за 67 мс; после ухода курсора анимация появления сбрасывается. Системное уменьшение движения отключает анимацию. `/tests/source-report.html` на Vite показывает экран на синтетических данных без обращения к API; `npm test` проверяет также границы периодов.
- Enter отправляет сообщение, Shift+Enter добавляет строку. Поле растёт примерно до десяти строк и разворачивается кнопкой. Во время ответа доступна остановка.
- Ответы, таблицы и предоставленные моделью рассуждения отображаются в чате. Рассуждения появляются после получения соответствующего шага модели; токенового стриминга нет. Если провайдер их не передаёт, блок отсутствует.
- Markdown-таблицы и «Данные ответа» оформлены общей рамкой и сеткой с лавандовой шапкой, занимают ширину ответа и сохраняют Markdown-выравнивание. Длинный текст переносится; широкие таблицы прокручиваются внутри рамки, в том числе с клавиатуры. `/tests/design.html` показывает числовую таблицу и длинные подписи, `?wide` — десять колонок на синтетических данных.
- Список моделей в поле ввода и локальный профиль открывают одни настройки. Выберите провайдера, введите ключ, получите список доступных моделей и выберите модель. OpenAI, OpenRouter, DeepSeek, Gemini и совместимые HTTPS API поддерживаются через ChatLiteLLM. Системная модель берётся из `AGENT_MODEL`; название не зашито в UI. Усилие зависит от семейства модели, а окончательная поддержка — от провайдера. Anthropic thinking-модели по прежнему не поддерживаются.
- При добавлении модели сначала показана короткая подборка с пояснениями; остальные модели раскрываются отдельно и доступны через поиск по названию и ID. Для провайдеров без подборки сразу открыт каталог с поиском. Подборка OpenAI хранится в `backend/workspace/models.py` (`MODEL_RECOMMENDATIONS`, дата проверки и ссылка на документацию рядом), пересекается с живым `/models` по точным ID и требует обновления при смене рекомендуемых семейств. API OpenAI не присылает рекомендации. Голосовые и другие заведомо неподходящие модели отфильтрованы; если OpenAI сообщает `shutdown_date`, отключённые модели исключаются, а будущая дата показывается в каталоге без рекомендации. При добавлении повторно проверяется наличие модели в каталоге по ключу; это не проверка генерации или совместимости вызова инструментов — она выясняется при первом запросе в чате.
- Отправка имеет идентификатор запроса. После потери связи повторная проверка не создаёт второй ответ; незавершённая отправка сохраняется в текущей вкладке. После перезагрузки страницы выполняющийся ответ подхватывается с сервера. Перезапуск backend помечает прерванные ответы и позволяет повторить их вручную.

## Графики и показатели в ответах

В ответе агента доступны карточки показателей (значение, сравнение с указанным периодом, необязательная мини-динамика) и графики line/area/bar с несколькими рядами. Цвет привязан к ключу метрики и сохраняется между карточками, графиками и ответами. Под графиком раскрывается таблица значений; доступны подсказки и навигация стрелками. На телефоне карточки располагаются друг под другом. У графиков нет анимации движения; пропуски не соединяются и не заменяются нулями, шкала включает ноль.

Агент получает рекомендации и примеры из `backend/workspace/answer_visuals.py` через контекст рабочего чата. Формат — JSON версии 1 в fenced-блоке `dig-visual` внутри обычного Markdown. Блок остаётся в `message.content`, поэтому расположение между абзацами, сохранение, перезагрузка и контекст следующего вопроса используют существующую историю. Старые ответы не преобразуются автоматически. Скопированный ответ содержит читаемые показатели и таблицу вместо служебного JSON. Обычные блоки кода, рассуждения и документ проекта не интерпретируются как визуализации.

Контракт и ограничения проверяет `src/answer-visuals.ts`, отображение — `src/AnswerVisual.tsx` и `src/answer-visuals.css`. До четырёх визуализаций в ответе, шести карточек в блоке, четырёх рядов и 120 точек в графике; один блок — до 64 000 символов. Неизвестные версии, неполные или повреждённые блоки дают понятное сообщение, сохраняя остальной ответ. Исполняемый код и произвольные настройки библиотеки не принимаются. Корректность чисел относительно источника остаётся задачей агента: проверка формата не доказывает достоверность аналитики.

`/tests/visuals.html` — изолированный пример на синтетических данных; `?edges` показывает отрицательное значение, одну точку и ошибочный блок. `/tests/design.html?visuals` показывает визуализации в компоновке чата, `/tests/workspace.html?visuals` — отправку и ответ через синтетический API. `npm test` проверяет контракт, в том числе реальные примеры из системной инструкции. `test_workspace.py` проверяет передачу инструкции, ответ в job API, сохранение, восстановление и передачу блоков в следующий запрос. Эти проверки не обращаются к поставщику модели.

## Конструктор Яндекс Метрики

Разделы слева — готовые наборы группировок: каналы, UTM, аудитория, устройства, страницы входа, география, цели и параметры визитов. «Разбить по…» выбирает до трёх измерений, например страна → устройство → браузер. «Показатели» выбирает до восьми метрик из посетителей, визитов, просмотров, отказов, глубины, времени, новых посетителей и четырёх показателей выбранной цели. Цели загружаются из счётчика при открытии раздела; доступны поиск по названию/ID, достижения, конверсия, целевые визиты и посетители. Каталог намеренно объединяет совместимые показатели визитов; карты поведения, Вебвизор, настройка счётчика и отдельный конструктор электронной коммерции не реализованы.

«Фильтры» применяют до восьми условий ко всему отчёту с объединением И/ИЛИ. Есть равно, не равно, содержит и не содержит; для категориальных признаков доступны только первые два. Нажатие строки таблицы открывает её сегмент. Такой переход и поиск в таблице доступны при объединении И: интерфейс не заменяет смысл уже заданного ИЛИ. Таблица сортируется на сервере и листается до 200 страниц; CSV выгружает текущую страницу либо все загруженные временные точки. Даты, фильтры и показатели одинаковы у итогов, графика и таблицы. Сравнение запрашивает предыдущий период той же длины с теми же условиями, показывает изменения карточек и вторую линию с собственными датами в подсказке.

Интервалы графика: минута, 10 минут, час, день, неделя и месяц. «Авто» выбирает 10 минут для одного дня и день для нескольких. Интерфейс ограничивает график 1600 точками: минутный интервал доступен за один день, 10 минут — до 11 дней, часы — до 66 дней. При расширении диапазона слишком мелкий интервал заменяется на «Авто». Будущие точки текущего дня не рисуются, отсутствующие значения сохраняются как пропуски. Линия, заливка и столбцы переключаются без обращения к API. В параметрах расчёта есть точность, атрибуция и отображение неопределённых групп. Под отчётом видны минимальная доля выборки, скрытые малые группы и задержка данных, включая период сравнения.

Кеш backend ограничен 128 записями в памяти и очищается при перезапуске. Записи с сегодняшним днём живут 60 секунд, остальные — 5 минут. Итоги, временные точки и страницы таблиц кешируются отдельно, одинаковые одновременные запросы объединяются. Источник и его версия, показатели, фильтры, атрибуция, точность, даты и параметры соответствующей части отчёта входят в ключ. Смена страницы или группировки использует прежние итоги и график; смена интервала использует прежние итоги и таблицу. «Обновить» обходит кеш.

При сужении диапазона, например 30 → 7 дней, дневные и более мелкие точки можно вырезать из свежей полной загрузки с теми же условиями. Это разрешено только без sampling и скрытых малых групп. Недельные и месячные точки не вырезаются: граничные интервалы зависят от периода. Уникальные пользователи, проценты и средние за новый диапазон всегда берутся из отдельного точного ответа Метрики; таблицы тоже запрашиваются за выбранный диапазон. Дневные уникальные пользователи не складываются, часовая детализация не выдумывается из дневной.

API конструктора: `GET /api/sources/{id}/explorer/catalog`, `GET /api/sources/{id}/explorer/goals`, `POST /api/sources/{id}/explorer`. Доступ требует сессии рабочего пространства и подключённого источника. Браузер отправляет только проверяемые псевдонимы полей и условия; реквизиты и выбор счётчика принадлежат backend. Старые API отчётов и агентские инструменты сохранены. `backend/test_metrika_explorer.py` проверяет точные итоги, переиспользование и изоляцию кеша, цели, выборки, сравнение, страницы и валидацию; `test_workspace.py` проверяет границы API. В `/tests/source-report.html` небольшой диагностический вывод фиксирует анимацию первого появления и движения подсказки; fixture не входит в production.

API-справочники: [Метрика](https://yandex.com/dev/metrika/ru/stat/openapi/bytime), [GA4](https://developers.google.com/analytics/devguides/reporting/data/v1/quickstart), [Matomo](https://developer.matomo.org/api-reference/reporting-api), [Amplitude](https://www.amplitude.com/docs/apis/analytics/dashboard-rest), [Mixpanel](https://developer.mixpanel.com/reference/list-recent-events), [PostHog](https://posthog.com/docs/api/queries).

## Информация о проекте

На широком экране ширина списка проектов слева и документа справа меняется перетаскиванием внутреннего края. При наведении край подсвечивается выбранным акцентным цветом. Размеры запоминаются в браузере, двойной щелчок по краю возвращает исходную ширину. Доступны также стрелки с клавиатуры (Shift увеличивает шаг), Home и End. Ограничения ширины сохраняют место для чата; на телефоне документ по-прежнему открывается на весь экран.

В списке источников каждого проекта есть сводка. Пока она пустая, красная плашка «Нет информации о проекте» предлагает описать проект в чате: сохраняется приглашение ассистента, поле получает фокус и краткую подсветку. Это действие не вызывает модель. Затем агент сохраняет полезные факты и задаёт уместные уточняющие вопросы. Когда контекста достаточно или пользователь хочет перейти к своему вопросу, агент завершает уточнения. Кнопка «Перейти к вопросам» позволяет сделать это вручную. Режим относится только к текущему чату; его состояние переживает перезагрузку.

В любом чате проекта агент получает актуальную сводку при каждом запросе и должен добавлять новые подтверждённые сведения без повторений, сохраняя ручные правки. Шаблон включает описание продукта, аудиторию, пользовательский путь, бизнес-модель, цели и метрики, особенности аналитики, контекст и ограничения. Неизвестные разделы можно оставить пустыми. Текст сводки и вложенных документов рассматривается как данные, а не инструкции.

После успешного сохранения сервер добавляет к ответу уведомление с описанием изменений и ссылкой «информацию о проекте». Уведомление сохраняется и при прерывании ответа после записи. Ссылка и обычная плашка открывают документ справа; на узком экране панель занимает весь экран. Ручное изменение доступно через «Редактировать», затем «Сохранить». Несохранённый черновик хранится в этом браузере и восстанавливается при следующем входе в редактор. Если документ успел измениться, сохранение старой версии отклоняется: интерфейс показывает свежий текст и сохраняет черновик для переноса правок.

Документ хранится в поле `info` проекта в том же игнорируемом `workspace.json`, общий для всех его чатов. Максимум — 30 000 символов. API: `GET/PUT /api/projects/{id}/info`, `POST/DELETE /api/chats/{id}/project-interview`. Запись требует актуального `revision` и обычного токена рабочего пространства. Отдельные инструменты `read_project_info`, `update_project_info`, `finish_project_interview` возвращают результат напрямую и не входят в повторно исполняемые аналитические data handles. Текст правил и шаблон находятся в `backend/workspace/project_info.py`; провайдер модели и его настройки остаются общими с остальным чатом.

`make test-workspace` также запускает `backend/test_project_info.py`: сохранение и восстановление, конкурирующие правки, изоляция проектов, отмена, уведомления и реальный цикл LangGraph с тестовой моделью. Следование свободным инструкциям о полноте описания и уместности вопросов зависит от выбранной модели.

## Хранение и границы

Это один локальный профиль, без регистрации и разграничения пользователей. Порты Compose опубликованы только на loopback. Для публичного многопользовательского размещения потребуются аутентификация и отдельные пользовательские пространства.

Проекты, подключения, транскрипты и задания сохраняются в `workspace.json` рядом с настроенным файлом checkpoints в игнорируемой папке `vm/backend/checkpoints/`. LangGraph сохраняет полный контекст в SQLite; если служебный checkpoint удалён по TTL, контекст восстанавливается из текста диалога (без прежних промежуточных результатов инструментов). Удаление чата удаляет и его checkpoint. Старая история legacy-клиента автоматически в проекты не импортируется.

В форме добавления модели «Запомнить ключ на этом компьютере» включено по умолчанию. Флажок шифрует реквизиты Fernet, ключ шифрования находится рядом в `workspace.key`. Если снять флажок, ключ действует до перезапуска backend; обычная и принудительная перезагрузка страницы его не удаляют. Резервная копия должна включать оба файла; шифрование не защищает от администратора, читающего оба. Настройка источников данных сохраняет собственный выбор срока хранения. Несекретные параметры из каталога полей (ID счётчика, регион и т. п.) сохраняются отдельно от ключа, чтобы не вводить их заново при переподключении. Для старых подключений они также восстанавливаются из доступных реквизитов и метаданных. API не возвращает секреты; браузер хранит только черновики, выбранный чат, состояние папок и идентификаторы отправки.

Имя добавляемой модели берётся из каталога автоматически. При вводе ключа интерфейс и backend отсеивают только явные ошибки вставки: пробелы внутри, управляющие и не-ASCII символы, заголовок Authorization/Bearer вместо самого ключа. Пробелы по краям убираются. Фиксированная длина и префикс не проверяются: официальная документация [OpenAI](https://developers.openai.com/api/reference/overview#authentication) не задаёт строгую схему ключа. Действительность ключа проверяет поставщик при получении списка моделей. Страница `tests/workspace.html` на Vite позволяет проверить форму и каталог на синтетических данных без внешних запросов.

Инструменты API находятся в `backend/connectors/`, управление проектами и заданиями — в `backend/workspace/`. Они подключены через существующий механизм обнаружения инструментов; агент не получает произвольный SQL. Каждый экземпляр AnalyticsService видит только источники своего проекта. Изначальный проект сохраняет операторский dataset как fallback, пока к нему не подключлены API-источники; новые проекты его не наследуют.

## Проверки

`make test-workspace` из `webreport/` запускает изолированные проверки реквизитов, границ источников, расчётов, повтора запросов, восстановления истории и API. `npm run build` проверяет TypeScript и сборку. Legacy `make test-e2e` относится только к старому Streamlit.

При текущей реализации живыми запросами проверены Метрика и системная модель через LiteLLM, включая ответ на вопрос по данным. Другие провайдеры реализованы по API-документации и требуют проверки с реальными реквизитами. Внешние API и доступные модели могут зависеть от региона, тарифного плана и прав ключа.
