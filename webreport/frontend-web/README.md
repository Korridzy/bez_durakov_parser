# «Без дураков» — рабочее пространство WebReport

Основной интерфейс WebReport: React, TypeScript и Vite. Docker собирает статические файлы и раздаёт их через nginx; `/api` проксируется в FastAPI. `frontend/` — сохранённый legacy Streamlit-клиент, в основном Compose он больше не запускается и не развивается.

## Запуск и разработка

Обычный запуск: `Start-WebReport.cmd` в корне или `make webreport-start`. Сборка интерфейса входит в запуск. Node.js на хосте для Docker не нужен.

Для разработки с уже работающим backend:

```powershell
cd webreport/frontend-web
npm ci
npm run dev
```

Vite использует `http://127.0.0.1:28000`. При другом порте задайте `WEBREPORT_DEV_API`. Проверка типов и production-сборка: `npm run build`.

## Работа с интерфейсом

- В интерфейсе используется короткое название «Без дураков» из названия исходного проекта; WebReport остаётся техническим названием компонента и команд запуска.
- «Локальный профиль → Акцентный цвет» меняет оформление сразу: шесть палитр и произвольный цвет. Выбор сохраняется в этом браузере. Акцент используется в навигации, кнопках, сообщениях пользователя и выбранных элементах отчётов; фирменные значки сервисов сохраняют свои цвета. При светлом пользовательском цвете оттенок кнопок автоматически затемняется для читаемости белых подписей.
- Боковая панель плавно выезжает и скрывается, учитывает системное уменьшение анимации и сохраняет состояние папок. Папку можно переключить нажатием на всю её строку (кроме отдельных кнопок действий), в том числе на название. Названия текущего проекта и чата остаются в боковой панели.
- Новый чат встречает фразой «Хей. Какие вопросы по проекту?». В пустом проекте — «Yo, чел. Мне нужна инфа, чтобы дать тебе толковые советы» и крупная кнопка добавления источника; логотипа и предложенных запросов в центре нет.
- Источники находятся внутри поля ввода: значок сервиса, название и состояние подключения. Плашка открывает отчёт сразу на весь экран; при утраченном или отклонённом ключе — форму его повторного ввода. Ошибки подключения отмечены восклицательным знаком; временные ошибки сервиса можно повторить в отчёте. Статус обновляется после запросов, при возвращении во вкладку и перед открытием источника. Данные операторского проекта учитываются только когда API-источников нет, как в backend.
- Настройки источника показывают ID и остальные несекретные параметры, а также наличие действующего ключа. Его можно оставить при сохранении настроек или заменить. Списки сервисов, регионов и периодов оформлены выбранным акцентным цветом и доступны с клавиатуры: стрелки, Home/End, ввод начала названия, Enter и Escape.
- Под ответом находятся копирование, название модели, длительность и локальное время получения. Длительность новых ответов сохраняется сервером в `duration_seconds`; старая история без этого поля показывает имеющиеся сведения. У сообщений нет аватаров.
- Значки сервисов загружаются из локальных файлов; [список оригинальных источников](public/providers/README.md).
- Проекты и чаты находятся слева. Источники проекта доступны всем его чатам; новый проект начинает без источников. Плюс у папки открывает новый чат, который сохраняется с первым сообщением.
- Подключения добавляются через «Источники» в шапке или плюс в поле ввода. Нажатие на название источника открывает сводку. Подробные разделы загружаются при выборе; страницы и цели Метрики можно догружать по 50 строк. Период ограничен 366 днями, ответы кешируются на пять минут.
- Enter отправляет сообщение, Shift+Enter добавляет строку. Поле растёт примерно до десяти строк и разворачивается кнопкой. Во время ответа доступна остановка.
- Ответы, таблицы и предоставленные моделью рассуждения отображаются в чате. Рассуждения появляются после получения соответствующего шага модели; токенового стриминга нет. Если провайдер их не передаёт, блок отсутствует.
- Список моделей в поле ввода и локальный профиль открывают одни настройки. Выберите провайдера, введите ключ, получите список доступных моделей и выберите модель. OpenAI, OpenRouter, DeepSeek, Gemini и совместимые HTTPS API поддерживаются через ChatLiteLLM. Системная модель берётся из `AGENT_MODEL`; название не зашито в UI. Усилие зависит от семейства модели, а окончательная поддержка — от провайдера. Anthropic thinking-модели по прежнему не поддерживаются.
- Отправка имеет идентификатор запроса. После потери связи повторная проверка не создаёт второй ответ; незавершённая отправка сохраняется в текущей вкладке. После перезагрузки страницы выполняющийся ответ подхватывается с сервера. Перезапуск backend помечает прерванные ответы и позволяет повторить их вручную.

## Подключения

| Источник | Доступ | Доступные отчёты |
| --- | --- | --- |
| Яндекс Метрика | ID счётчика и OAuth-токен с `metrika:read` | Посетители, визиты, просмотры, отказы, динамика по дням, каналы, устройства, страницы, география, цели |
| Google Analytics 4 | Property ID и JSON сервисного аккаунта с ролью Viewer на ресурсе; включённый Data API | Аудитория, сеансы, просмотры, отказы, каналы, устройства, страницы, страны, события |
| Matomo | Публичный HTTPS URL, ID сайта, token_auth пользователя с правом просмотра | Посещения, просмотры, каналы, устройства, страницы, страны, события, цели |
| Amplitude | API key, Secret key, регион US/EU | Активные пользователи по дням, среднее DAU и каталог событий |
| Mixpanel | Project ID, имя и секрет сервисного аккаунта, регион US/EU/IN | Объёмы событий и динамика для топ-50 типов событий за последние 31 день; ограничение подписано в сводке |
| PostHog Cloud | Project ID, Personal API key с query:read и project:read, регион US/EU | Пользователи, события, просмотры, динамика, события, страницы, устройства, страны |

Отчёты учитывают различия API: например, сумма дневных уникальных пользователей не выдаётся за уникальных пользователей всего периода. Sampling и ограничения выборки показываются рядом с данными. Это базовые отчёты, а не полный набор функций кабинетов сервисов.

API-справочники: [Метрика](https://yandex.com/dev/metrika/ru/stat/openapi/bytime), [GA4](https://developers.google.com/analytics/devguides/reporting/data/v1/quickstart), [Matomo](https://developer.matomo.org/api-reference/reporting-api), [Amplitude](https://www.amplitude.com/docs/apis/analytics/dashboard-rest), [Mixpanel](https://developer.mixpanel.com/reference/list-recent-events), [PostHog](https://posthog.com/docs/api/queries).

## Хранение и границы

Это один локальный профиль, без регистрации и разграничения пользователей. Порты Compose опубликованы только на loopback. Для публичного многопользовательского размещения потребуются аутентификация и отдельные пользовательские пространства.

Проекты, подключения, транскрипты и задания сохраняются в `workspace.json` рядом с настроенным файлом checkpoints в игнорируемой папке `vm/backend/checkpoints/`. LangGraph сохраняет полный контекст в SQLite; если служебный checkpoint удалён по TTL, контекст восстанавливается из текста диалога (без прежних промежуточных результатов инструментов). Удаление чата удаляет и его checkpoint. Старая история legacy-клиента автоматически в проекты не импортируется.

По умолчанию ключ действует до перезапуска backend; обычная и принудительная перезагрузка страницы его не удаляют. Флажок «Сохранять ключ после перезапуска сервера» шифрует реквизиты Fernet, ключ шифрования находится рядом в `workspace.key`. Резервная копия должна включать оба файла; шифрование не защищает от администратора, читающего оба. Несекретные параметры из каталога полей (ID счётчика, регион и т. п.) сохраняются отдельно от ключа, чтобы не вводить их заново при переподключении. Для старых подключений они также восстанавливаются из доступных реквизитов и метаданных. API не возвращает секреты; браузер хранит только черновики, выбранный чат, состояние папок и идентификаторы отправки.

Инструменты API находятся в `backend/connectors/`, управление проектами и заданиями — в `backend/workspace/`. Они подключены через существующий механизм обнаружения инструментов; агент не получает произвольный SQL. Каждый экземпляр AnalyticsService видит только источники своего проекта. Изначальный проект сохраняет операторский dataset как fallback, пока к нему не подключлены API-источники; новые проекты его не наследуют.

## Проверки

`make test-workspace` из `webreport/` запускает изолированные проверки реквизитов, границ источников, расчётов, повтора запросов, восстановления истории и API. `npm run build` проверяет TypeScript и сборку. Legacy `make test-e2e` относится только к старому Streamlit.

При текущей реализации живыми запросами проверены Метрика и системная модель через LiteLLM, включая ответ на вопрос по данным. Другие провайдеры реализованы по API-документации и требуют проверки с реальными реквизитами. Внешние API и доступные модели могут зависеть от региона, тарифного плана и прав ключа.
