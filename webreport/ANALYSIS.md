# Универсальный аналитический агент

Чат сохраняет прежний LangGraph-цикл и выбранную пользователем модель. Дополнительные инструменты позволяют осмотреть подключённые источники, получить данные, выполнить написанный моделью Python и опубликовать график. Отсутствие нужных данных — допустимый результат анализа: агент должен объяснить пределы вывода и доступное приближение.

## Инструменты

- `inspect_data()` — метаданные источников проекта и список доступных операций с аргументами. Не скачивает таблицы целиком.
- `query_data(operation, arguments)` — вызывает одну операцию существующего реестра и сохраняет неизменяемый результат. Возвращает `result_id`, структуру, небольшой пример и параметры получения. Повторное чтение результата не повторяет API-запрос.
- `read_result(result_id, table, offset, limit)` — читает сохранённые строки. Смещение относится к локальному результату; для следующей страницы API нужны аргументы пагинации в новом `query_data`.
- `run_python(code, inputs)` — исполняет Python над сохранёнными результатами. Доступны pandas, NumPy, math, statistics, datetime и SQL над локальными копиями таблиц. Код присваивает итог переменной `result`; DataFrame преобразуется в `{"rows": [...]}`. Входы задаются как `{"visits": "result_id"}`; полное содержимое находится в `inputs['visits']`, таблица — в `frames['visits']`. Каждый запуск начинается с чистого процесса. Промежуточные результаты можно передавать следующему запуску.
- `publish_chart(...)` — строит представление из столбцов сохранённого результата. Модель не передаёт в этот инструмент отдельный массив чисел. Возвращаемая Markdown-ссылка `#analysis-ID` открывает правую панель. На телефоне панель занимает экран.

Новые API-операции описаны в `connectors/service.py`: `source_schema`, `source_documentation`, `metrika_timeseries`, `analytics_query`. Метрика поддерживает прямые имена полей Reporting API, фильтры, пагинацию, точность, сортировку и часовой пояс `+03:00`. Временные ряды возвращаются в длинном формате: время × страна × метрики. Для нескольких линий агент может сделать `pivot`. Каталог основных полей дополняется чтением официального полного справочника; цели берутся у сохранённого счётчика. Наличие поля в каталоге не означает наличие записанных значений.

GA4 позволяет запросы `runReport` и получает каталог полей ресурса через Metadata API. У Matomo, Amplitude и Mixpanel разрешены перечисленные в `native_queries.py` операции чтения. PostHog принимает SELECT/WITH через свой HogQL reporting endpoint. У каждого источника остаются собственные семантика, фильтры, доступные поля и ограничения API. Другие провайдеры требуют проверки с действующими реквизитами.

SQL в `run_python` работает только по переданным копиям данных в SQLite внутри исполнителя. Это не новое хранилище игровых данных и не произвольный SQL к операторской базе. Живая база по-прежнему доступна через инструменты модуля `dataset.tools_module`; они тоже вызываются через `query_data`. API-источники и операторский fallback выбираются по прежнему правилу проекта.

## Представление результатов

Доступны линии, области, столбцы, составные столбцы, распределения по интервалам, диаграммы рассеяния, тепловые карты, воронки и таблицы. Для всех серий одной диаграммы нужны совместимые единицы. Пропуски сохраняются как `null`. Воронка проверяет невозрастающие количества, но доказательство порядка событий остаётся задачей расчёта. Независимые достижения целей нельзя выдавать за последовательную воронку.

Панель показывает график, переключаемые серии, таблицу точных значений, экспорт CSV, дату фиксации и параметры/код расчёта. Старые встроенные `dig-visual` ответы продолжают работать. Копирование ответа сохраняет ссылку на результат в этом чате; ссылки не являются публичными.

## Изоляция и хранение

`analysis` — отдельный контейнер из `Dockerfile.analysis`, запускаемый Compose вместе с backend. Он не получает ключи, базу, Docker socket или тома проекта. Его файловая система доступна только для чтения, временные файлы находятся в ограниченном tmpfs. Приватная сеть `analysis-network` соединяет только backend и исполнитель, порты исполнителя на хост не публикуются.

Служебный процесс принимает ограниченный JSON и запускает одноразовый процесс с UID 65534 и очищенным окружением. Перед исполнением кода включается allowlist системных вызовов через libseccomp; при невозможности включения расчёт не запускается. Сеть, запуск процессов, exec, ptrace и изменение привилегий отсутствуют в списке. Изоляция складывается из отдельного контейнера, отсутствия секретов/томов, смены UID, фильтра системных вызовов и лимитов ресурсов. Это не Python-фильтр строк и не `exec` в процессе FastAPI.

Лимиты запуска: 15 секунд CPU, 22 секунды общего времени, 1 GiB адресного пространства, 8 входных результатов, 8 MiB входного JSON, 32 000 символов кода, 4 MiB результата. Диагностический вывод ограничен. В одном исполнителе одновременно работает один расчёт. Отмена чата прекращает ожидание и запрещает запись результата; уже исполняющийся процесс завершится по своему лимиту не позднее 22 секунд.

Результаты и графики находятся в `analysis/<chat_id>/` рядом с `workspace.json` в игнорируемом `vm/backend/checkpoints/`. Лимит одного чата — 128 MiB. Удаление чата удаляет его файлы; результат другого чата недоступен через инструменты и API. Источник, параметры, время получения и код сохраняются для воспроизводимости. Внешний API может менять данные между разными запросами: каждый результат фиксирует именно свой ответ.

Чату с harness выделено до 32 циклов агента, 60 вызовов его аналитических инструментов и 600 секунд общего времени. Старый `/api/chat` сохраняет прежние настройки. Ключи моделей и механика подключения провайдеров не меняются.

## Запуск и проверка

Обычный `Start-WebReport.cmd` или `make start DATASET=<name>` собирает и запускает исполнитель по зависимости backend. При обновлении его библиотек или файлов пересоберите `analysis`; Python-модули backend монтируются как прежде.

```bash
docker compose build analysis
docker compose up -d analysis
make test-workspace
docker compose run --rm --no-deps -e BD_CONFIG_LOCAL_FILE= -e RUN_ANALYSIS_INTEGRATION=1 backend python test_analysis.py
```

Последняя команда проверяет настоящий изолированный Python, pandas/SQL, запреты сети/процессов/чтения окружения служебного процесса, восстановление после ошибки/таймаута и полный цикл LangGraph с детерминированной моделью. Внешние модель и аналитический сервис в этих тестах не вызываются.

Для UI: `npm run dev`, затем `/tests/workspace.html?analysis` — настоящий App с синтетическими данными. Проверяются ссылка в ответе, правая панель, два ряда, пропуск, таблица и узкий экран. `npm run build` проверяет типы и сборку.
